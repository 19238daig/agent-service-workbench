# 售后自助处理

普通用户从侧栏进入「售后自助处理」，也可以在新对话发送「包装里缺少说明书，帮我找型号 DEMO-X1 的说明书」。系统识别到明确的型号后自动查找。缺少型号时，打开表单请用户补充。已有工单可以从工单详情发起「自助处理或转人工」。

## 核对说明书并解决

1. 按商品型号精确查找已发布、公开、在有效期内的说明书，并核对原文件的哈希。系统展示匹配的型号、资料标题、版本和发布者。
2. 下载并核对说明书。问题已解决时，勾选确认并点「确认已解决」。系统再次核对原文件和工单版本。
3. 办理成功后，工单显示「已解决」。已有的未分派、待处理的通用说明书工单会更新原记录。未关联工单时，会新建一张已解决的通用服务工单，方便用户追溯。

## 转给人工客服

没有合适资料、资料无法使用，或涉及破损和赔偿时，用户可点「转人工处理」。也可在聊天发送「我的包裹破损了，请转人工客服」，并核对准备提交的信息。提交后，工单记录问题摘要、已核验的关联订单信息和下一步核实事项。能用的原处理人会保留，否则优先分派给可用客服。没有可用人员时，回执会显示「等待分派客服」。已经走审批流程的工单保留原业务状态。

客服可在「客服工作台 → 待我处理」查看工单和处理记录。涉及赔偿或退款时，系统继续使用原有的人工和审批流程。这条自助流程没有支付能力。

## 准备可查找的说明书

升级数据库后再启动应用。说明书走已有知识入库流程。管理员在「知识管理」上传有使用权限的原文件，将可见范围设为「公开」，并将来源标识设为 `manual:<完整型号的小写>`，例如 `manual:demo-x1`。核对资料、版本和适用型号后发布。新版本沿用同一来源标识。这条查找使用精确型号，因此不要求重建向量索引。对话里的普通知识检索继续使用原有索引。

本地演示可以用以下命令添加一个虚构型号的可用说明书。

```powershell
.\.venv\Scripts\python.exe -m smart_cs.delivery init
.\.venv\Scripts\python.exe scripts/seed_self_service_demo.py
```

用 `customer-a` 查找 `DEMO-X1` 可验证下载与确认。换成未录入的 `DEMO-X2` 可验证无匹配时的转人工。发布到真实环境时，需要录入实际型号对应的来源材料，并开通负责接手的客服账号。

## 数据库记录

查找只保存本次自助处理记录。明确确认或转人工时，服务把工单、操作事件和执行回执放在同一个事务中提交。

| 表 | 内容 |
| --- | --- |
| `self_service_cases` | 用户发起的请求、匹配的说明书、确认决定及处理回执。同一请求重复提交会返回已保存的结果。 |
| `tickets` | 工单当前状态、处理人和版本。 |
| `ticket_events` | 用户确认解决或转人工的记录，包含资料版本或客服待核实事项。 |
