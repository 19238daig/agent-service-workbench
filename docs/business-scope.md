# 第一阶段业务边界与数据契约

业务域为虚构电商店铺的售后咨询与申请登记。它不是实际金融客服，也不执行真实支付退款。当前用户标识为本地演示工作区 ID，不是登录认证。

| 场景 | 第一阶段行为 | 禁止宣称 |
| --- | --- | --- |
| 退款、配送、商品与账户说明 | 从已发布的演示资料检索并回答，最终仍经合规审查 | 将虚构规则说成真实平台政策或法律规定 |
| 明确提出建单 | 提取结构化字段，写入 PostgreSQL 工单与创建事件 | 工单创建等于退款批准或款项到账 |
| 查询工单 | 按工作区过滤，读取数据库当前状态 | 仅凭模型回忆或知道编号就跨工作区查询 |
| 订单数据 | 提供工作区范围内的只读订单 API，供后续工具接入 | 当前 Agent 已能核验全部申请条件或执行订单修改 |
| 安全咨询 | 给出官方核实建议并审查内容 | 已冻结账户、报警、转交人工或追回资金 |
| 多任务、完整审批、并发幂等 | 数据集中明确标为规划能力，后续阶段实现 | 对应能力已生产化完成 |

角色契约：customer 查看本人授权资源并提出申请；support 在规定范围处理工单；admin 管理知识和配置。数据库目前只有演示角色字段，完整登录、RBAC、审批与人员工作台属于后续任务。传入另一个工作区 ID 不构成认证，因此服务保持本机绑定，不应公开部署。

工单类型：refund、complaint、general；为兼容既有测试适配器保留 claim/account_open/account_change 枚举，不将其描述为已接通的真实业务。优先级：low/medium/high/urgent。状态：created、processing、pending_review、resolved、closed、escalated；状态机和事件在数据库仓储中执行。

订单金额使用定点数和 CNY，归属、金额和时间来自数据库；提供订单号建单时必须属于该工作区。初期允许无订单关联的服务记录，完整退款申请槽位/政策校验在后续动作计划阶段补齐。

验收应分别报告：数据库持久化、归属过滤、模型调用路径、数据集完整性、分类基线；不能将合成分类测试分数当作四 Agent 任务成功率。
